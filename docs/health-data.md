# 健康数据读取与归并

首版由 iPhone 的 `HealthKitClient` 读取并构造 `ReadinessInput`，Watch 接收派生结果。没有健康数据写入、原始样本持久化、日志或服务器传输。系统授权流程完成不代表所有读取权限已允许；成功的空查询与查询失败分别处理。

## 读取范围

只请求实际使用的类型：睡眠分段、心率、SDNN、呼吸频率、睡眠腕温、血氧、活动能量、静息心率和体能训练。SDNN 使用毫秒；腕温使用摄氏度；血氧使用 0–1 比例；活动能量使用 kcal。不读取 RMSSD、逐搏记录、苹果最终评分、身高体重或出生日期。

先查询最近 49 晚所需的睡眠记录并归并会话，再按实际睡眠区间的 OR 条件读取夜间心率、SDNN、呼吸、腕温和血氧；不扫描未用于本版算法的 49 天全天心率。活动、训练和静息心率读取此前 28 天及今天。使用公开 `HKSampleQueryDescriptor` 异步 API，先调用 iOS 27 的 `earliestAuthorizedSampleDate(for:)`，按每个类型的受限读取起点收窄查询。该 API 没有返回某一类型不代表该类型已授权；空数据仍不能用来判断拒绝授权。

所有实际发出的查询及读取时间窗查询必须成功才能发布一次输入；任何查询错误都会向上抛出，不能自动替换成空数组。大批样本的归并和摘要在后台任务执行，可取消。夜间指标按开始时间排序，用二分查找定位会话范围，避免逐夜反复扫描完整历史数组。受限读取起点可能截断可用睡眠历史，这会自然反映为初始化记录不足，而不是补造完整睡眠。

仅处理截止查询时刻已结束的自动 Watch 记录。过滤未来记录、手动录入和仅表示卧床的记录；无样本不能推断用户拒绝了权限。HealthKit 中结束的睡眠片段不一定证明整个睡眠已经结束，Apple Watch 实际写入时机仍需在实机核验。

## 睡眠与来源

- `productType` 或设备型号必须标识 Watch。来源标识为 bundle identifier、productType、可用的 `HKDevice.localIdentifier` 的组合；不把第三方仅在 iPhone 记录的睡眠当作 Watch 测量。
- 同一来源中，相隔不超过 90 分钟的睡眠片段组成一个会话。跨午夜保持完整，主睡眠及午睡的日期归属由算法按会话结束日判断。
- 浅睡、深睡、REM 和未细分睡眠取时间并集；重叠时只算一次。明确清醒片段取并集并从睡眠中扣除。未观测间隙不会补成睡眠，也不会伪造成明确清醒。
- 只用睡眠片段决定会话分组，长时间清醒记录不能把午睡与夜间睡眠连接起来。边界外的清醒不计入该会话。
- 不同 Watch 来源的重叠会话只保留一个：有效睡眠时间较长者优先，其次详细分期覆盖，最后稳定来源标识。不把两只表的分期拼接，也不创建额外初始化夜晚。
- 会话标识由来源和最早睡眠起点构成。重复读取、片段顺序改变和后续追加分期不会随机产生新标识；修正真正的起点可以改变标识。

夜间体征优先使用与睡眠完全相同的来源；若某一类型未携带设备标识，只能回退到相同 bundle 和 productType。存在两个可区分的候选来源时不合并。有明确不同设备标识的记录绝不匹配。部分 HealthKit 记录缺少物理设备标识，此时不能保证区分同一 bundle 下两台同型号表；换表与同步后的来源表现是实机验收项。

体征以会话内有效样本中位数汇总，不使用全天静息心率冒充夜间心率。统计 SDNN 和心率样本数量；`heartRateCoverageSeconds` 表示首尾有效心率样本的时间跨度，不表示这段时间有连续监测。重复时间和值的样本只保留一次。

输入防护范围是实验性技术过滤：心率 20–250 bpm、SDNN 0.001–500 ms、呼吸 4–60 次/分、腕温 20–45 ℃、血氧 0.5–1。所有值必须有限。这些范围不是健康/异常诊断阈值；算法的出分门槛另见 `algorithm.md`。

## 活动归并

每一天只选择一个 Watch 数据来源，优先当日主睡眠来源，再按实际时间覆盖与稳定标识选择；不累加 iPhone 与 Watch 的记录。无活动能量样本时 `activeEnergy = nil`，有实际零值样本才可能产生 0。

活动能量样本按时间边界归并；重叠时优先更细的记录，避免把细分记录与汇总或重复导入相加。跨日样本按所覆盖的时间比例分配。这是基于区间内均匀分布的估计，与系统健身累计值可能存在差异，需要实机对照。

体能训练仅提供训练时长摘要。采用记录自身排除暂停后的时长，以区间比例分配并去除重叠，不再次累加运动热量。首版不读取运动耗能评级；`effortLoad = nil`。活动负荷规则使用真实活动能量代理，不能称为苹果训练负荷或运动评级算法。

当天静息心率仅使用当天真实 Watch 样本，并与同类型的历史每日值比较。缺失时保持 nil，不借用夜间均值或最近一次数值。

## 更新、指纹与后台

指纹为实际归并后的睡眠记录、非空活动日及有效数据截止时间的 SHA-256，使用稳定记录顺序及 `JSONEncoder.sortedKeys`。不把原始 UUID、未选中的来源、无用日间心率或空日期占位放入指纹。重复导入得到相同有效结果时不刷新生成时间；删除或修改真正影响汇总的记录会改变指纹。当前时钟本身不进入指纹。

`dataThrough` 只取实际入选的睡眠会话、能量/训练积分区间及当天静息心率记录的最晚有效时间；不采用整批原始数据的最大时间。夜间指标限定在对应睡眠会话内，不会把截止时间延长到无关白天测量。真正入选的新记录即使没有改变四舍五入后的分数，也可以推进数据截止时间；单纯多出一份重叠导入不产生更新。

授权流程曾完成后才能注册观察；每个类型仅创建一个观察查询。多个同时到达的事件由应用 Store 合并刷新。HealthKit 的 completion 在变更处理完成后调用，已停止的一代观察会直接结束回调。停止观察会移除查询并请求关闭对应后台投递。

后台按 `.hourly` 申请，系统可以拒绝注册或延后投递。注册失败和观察查询错误分别按类型归集，通过 `onStatus(String?)` 返回简短状态；观察恢复后可清除对应错误。应用不因一次前台读取成功就隐去仍存在的后台注册故障。前台读取继续可用；不承诺每小时必定更新。组件刷新和手机到 Watch 同步还受各自系统预算影响。

## 验证边界与官方接口

纯 Swift 睡眠测试覆盖：分期/未分期重叠、明确清醒扣除、未知间隙、跨午夜、多个来源、午睡及重复记录、未来数据、稳定会话标识。iPhone 数据处理测试通过内部纯值边界验证无关日间数据、未选来源和重复导入不改变指纹与截止时间，活动能量重叠不累加，有效值改变可被发现，空日期不制造更新。测试由工程集成阶段统一运行；合成数据不能证明 HealthKit 采样质量、后台调度或真实用户评分准确性。
