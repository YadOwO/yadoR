# 准备度 App 产品方案

创建日期：2026-09-18　｜　版本：0.1　｜　产品名：待定

为 Apple Watch Series 9 及后续机型提供与苹果 Readiness 尽量一致的核心功能：每日准备度评分、四档状态、影响因素解释、日间更新，以及手表上的快捷查看。评分使用独立算法，界面采用原生组件和独立视觉表达。

本方案定义首版产品范围与验收行为。苹果官方事实、我们的产品决定和待验证事项分别标注；算法权重及准确性不视为已经完成验证。

官方已确认：评分范围为 0–10，综合活动、生命体征和睡眠；支持 Series 12、Ultra 4，功能面向 13 岁及以上。个人基线需要过去 49 晚中至少 7 晚的睡眠佩戴记录，不要求连续 7 晚，也不是等待 49 晚。[O1](https://support.apple.com/zh-cn/guide/watch/flx4gnzby346/watchos)

四档边界为 0–1、2–4、5–7、8–10；中文支持文章分别使用“适度休整、量力而行、蓄势待发、火力全开”。部分手册将第一档写为“恢复”，本项目按数值边界与含义对齐。[O2](https://support.apple.com/zh-cn/128112)

官方 App 会解释影响因素，并可进入关联 App；iPhone 当前入口是“健身”中的准备指数。复杂功能和智能叠放组件属于官方已确认功能。[O1](https://support.apple.com/zh-cn/guide/watch/flx4gnzby346/watchos)、[O3](https://apps.apple.com/us/app/readiness/id6764448634)

未确认 Readiness 自身拥有独立历史评分曲线、日期回看或日内折线图。Vitals、Sleep 等关联功能中的历史图不自动转化成本项目需求。中文使用手册本次可经搜索索引读到正文，直接访问偶尔跳转至手册首页；其他官方来源可交叉核对核心功能。

## 2. 产品目标与首版边界

用户每天只需要完成三件事：看当前状态；了解主要原因；在活动或休息后查看更新。产品不要求用户记录主观状态，也不引导用户制定训练计划。

| 决策项 | 首版方案 | 决策性质 |
|---|---|---|
| 核心人群 | 使用 S9、S10、S11，希望获得准备度功能的用户 | 用户已确定方向 |
| 支持机型 | 首发验证 S9、S10、S11、S12；未来 Series 随实际适配扩展 | 产品决定；不提前承诺未发布硬件 |
| 系统门槛 | watchOS 27 / iOS 27 起 | 用户已确认；首版不承担更早系统的适配 |
| 产品形态 | Watch App + 配套 iPhone App；表盘复杂功能 + Watch 智能叠放组件 | 对齐官方使用场景 |
| 用户范围 | 首版按 13 岁及以上设计；商店内容年龄评级另行填写 | 参考官方功能适用年龄；两种年龄口径不混用 |
| 评分 | 0–10 整数、四档状态；独立算法 | 已确定 |
| 品牌与界面 | 独立名称、图标、主评分图形和文案；使用原生组件 | 已确定 |
| 数据方式 | 优先只读 HealthKit、本地计算与存储；不要求账号 | 保持产品简单的首版决定 |

S9 本身支持 watchOS 27；采用 27 作为最低系统是简化首版适配的选择，并非旧表计算准备度的硬件门槛。[watchOS 兼容列表](https://www.apple.com/os/watchos/)

Ultra、SE 暂不作为首发对外承诺，避免扩大验证范围。应用结构不应无故排斥具备所需数据的设备；是否加入支持列表由实机验证决定。

首版不做 AI 对话、训练计划、运动记录器、压力／身体电量等新分数、疾病诊断、社交、排行榜、订阅内容、复杂个性化设置。暂不增加独立历史准备度图、主动晨报通知或 iPhone 桌面组件；这些未被确认为当前需要对齐的官方功能。

## 3. 官方功能对照与交付范围

| 需求 | 官方体验 | 我们首版交付 | 差异与边界 |
|---|---|---|---|
| R1 当前评分 | 一个 0–10 分结果与四档分类 | 同样的范围与分档含义，提供一句状态说明 | 数值独立计算，不与苹果分数等同 |
| R2 三类因素 | 活动、生命体征、睡眠影响结果 | 显示三类因素当前状态和主要影响原因 | 不读取苹果的最终分类结果 |
| R3 深入了解 | 点击因素查看解释、进入关联 App | 提供每类因素的最小解释页；有受支持入口时可进入系统 App | 不重做完整 Fitness、Vitals、Sleep |
| R4 首次建立基线 | 满足佩戴和数据条件后生成评分 | 先读取已授权历史，不足时提示还缺哪些记录 | 使用已有旧表历史是我们的产品决定，需验证数据质量 |
| R5 日间调整 | 活动、午睡及日间体征变化后更新 | 获得有效新数据后重算，并注明更新时间 | 不承诺固定周期或即时送达 |
| R6 手表快捷查看 | 表盘复杂功能、智能叠放组件 | 两类入口都支持评分、状态、点击进入 App | 系统调度影响刷新；陈旧结果须可识别 |
| R7 iPhone 查看 | 在苹果“健身”中查看更多信息 | 在自己的配套 iPhone App 查看同一结果及因素 | 无法承诺插入苹果官方准备指数页面 |
| R8 无评分状态 | 条件不足时无结果 | 区分初始化、历史不足、当日缺数据、等待更新 | 空数据不能变成 0 分 |

R1–R7 的官方对照来自 [O1](https://support.apple.com/zh-cn/guide/watch/flx4gnzby346/watchos)、[O2](https://support.apple.com/zh-cn/128112)、[O3](https://apps.apple.com/us/app/readiness/id6764448634)。R8 的具体状态设计是为旧表和第三方数据限制补齐必要体验，不是新增健康功能。

## 4. 页面与核心流程

### 4.1 页面清单

| 页面／入口 | 用户看到什么 | 主要操作 | 首版限制 |
|---|---|---|---|
| 首次设置（iPhone） | 功能简介、独立算法说明、健康数据用途、当前准备情况 | 授权读取；查看设置指导 | 不重复建立账号；身高体重不无用途地重复采集 |
| Watch 今日页 | 当前评分、状态说明、三类因素、更新信息 | 查看因素说明；竖向滚动 | 第一屏优先分数与状态，不堆叠多种健康分数 |
| 活动因素页 | 当天活动和近期负荷为何影响评分 | 查看有关的运动摘要／受支持的系统入口 | 不增加开始运动、训练计划或完整运动日历 |
| 生命体征因素页 | 有效指标相对个人基线的变化；区分夜间与日间依据 | 查看指标与测量时间 | 不提供连续监护或疾病推断 |
| 睡眠因素页 | 最近主要睡眠的时长、规律、清醒片段及其影响 | 查看睡眠摘要／受支持的系统入口 | 不重做完整睡眠管理、闹钟或作息设置 |
| iPhone 今日页 | 同一个准备度结果，更易阅读的因素说明 | 进入同样的三类因素页及设置 | 无需增加多个导航栏目 |
| 表盘复杂功能 | 分数／状态或暂无结果 | 打开 Watch 今日页 | 仅适配适合表达该信息的系统尺寸 |
| 智能叠放组件 | 分数、状态、更新时间或缺数据提示 | 打开 Watch 今日页 | 不假设可常驻首位 |
| 说明与设置 | 算法概述、数据来源、权限指引、隐私与帮助 | 查看说明；清除本地派生结果 | 不开放算法权重编辑 |

三个因素页只解释“为何得到这个结果”。已有数据可展示少量数值及基线比较；不因技术上能读取更多数据而扩充模块。

所有系统跳转必须使用受支持的公开方式。未验证具体页面入口时，提供本 App 的简短解释及手动查看指引，不依赖猜测的私有 URL scheme。

### 4.2 首次使用

用户在 iPhone 查看用途说明并授权 → 查询可读历史 → 判断基线是否够用 → 已具备条件则生成首个结果，否则展示初始化进度 → Watch 接收或生成可用结果。

不要求已有足够健康记录的用户从安装当天重新累计 7 晚。各项权限由用户选择；未读到数据时不能直接判断用户拒绝了授权。

### 4.3 每日查看

主要睡眠结束，数据可读后生成当天初始结果 → 打开 Watch 或快捷入口查看 → 有疑问时点开三类因素 → 返回今日页。

主要睡眠跨过午夜仍按一个睡眠会话处理，归属于结束当天。白天补觉作为后续更新输入，不能重复计入同一段睡眠，也不能单独充当多个初始化夜晚。此为本产品的数据归属规则。

### 4.4 日间变化

新活动、体能训练、午睡或有效日间体征写入 → 去重并判断是否影响当前评估 → 重算结果与原因 → 在系统允许时更新页面和组件。

刷新时间与最新样本时间分别记录。页面注明的“更新”应代表确实处理了新的有效输入；仅重新打开页面或读到缓存，不伪装成新测量。无新数据时不凭时间流逝制造分数变化。

## 5. 评分与数据规则

### 5.1 对用户的结果

| 分数 | 官方含义 | 本产品暂定状态文案 |
|---|---|---|
| 0–1 | Recover | 建议休整 |
| 2–4 | Pace Yourself | 适当放缓 |
| 5–7 | Ready | 状态就绪 |
| 8–10 | Go For It | 适合挑战 |

保留分档语义与范围，状态解释独立撰写。文案表达对当天活动安排的参考，不保证运动安全。低分与“没有足够数据”必须呈现为不同状态。

每个有效结果同时带有三类因素的解释、评估所属日期、所用数据截止时间、结果生成时间和算法版本。用户界面只露出必要信息，算法版本放在说明页；不增加独立的置信度百分比或第二套“数据完整度评分”。

### 5.2 输入及可用性

| 数据 | 用途 | 可获得的公开输入 | 缺失时的产品处理 |
|---|---|---|---|
| 睡眠分段 | 估计睡眠恢复、规律及清醒片段 | `sleepAnalysis` | 最近主要睡眠缺失时不生成当天初始分数 |
| 夜间／日间心率 | 评估相对个人状态变化 | `heartRate`、`restingHeartRate` 等 | 区分时段与实际来源，不把全天静息心率充当夜间均值 |
| HRV | 与个人同类指标基线比较 | 首版基线优先采用 `heartRateVariabilitySDNN` | 长期无有效记录时不声称已经获得完整恢复评估 |
| 新版 RMSSD | 可作为后续适配的数据输入 | 系统 27 的 `heartRateVariabilityRMSSD` | 首版不依赖其存在；不得与 SDNN 拼接使用 |
| 腕温／呼吸／血氧 | 补充生命体征偏离判断 | 相应 HealthKit 类型 | 部分缺失可继续，明确未计入；不填 0 或假定正常 |
| 活动与体能训练 | 当天消耗和近期负荷 | `activeEnergyBurned`、`HKWorkout` | 当天没有运动不等同于缺权限或健康异常 |
| 运动耗能评级 | 估计训练负荷 | `workoutEffortScore`、`estimatedWorkoutEffortScore` | 缺评级时不伪造评级；采用已验证的替代或仅使用可用活动数据 |

当前公开 SDK 未发现直接读取苹果准备指数、睡眠评分和训练负荷最终结果的类型，相关中间结果也由本产品计算。[HealthKit 数据类型](https://developer.apple.com/documentation/healthkit/data-types)、[运动耗能评级接口](https://developer.apple.com/documentation/updates/healthkit)。本次也核验了本机 iOS/watchOS 27 的公开声明；详细 SDK 证据记录保存在原始调研目录，未随本项目归档。

睡眠模型先围绕时长、规律性和清醒片段形成独立评估；训练负荷参考近期与较长历史的比较。苹果训练负荷公开说明使用 7 天与 28 天窗口，但这并未公开其准备指数完整公式。[睡眠评分说明](https://support.apple.com/en-sg/guide/watch/apded441a669/watchos)、[训练负荷说明](https://support.apple.com/en-om/guide/watch/apde4c07a6cf/watchos)

### 5.3 冷启动与降级

首版拟采用“过去 49 晚至少 7 个有效夜晚”的启动窗口，优先回溯用户已授权的历史。这里复用的是可理解的产品门槛，并不意味着我们的算法已经获得苹果同等验证。

有效夜晚应有可用的主要睡眠记录和夜间心率；HRV 还须满足独立的基线覆盖要求。具体样本数量、覆盖时长和异常剔除阈值，必须在 S9 实机数据核验后写入算法规格，不能为了凑满 7 晚把无效样本算进去。

| 状态 | 判断依据 | 展示行为 |
|---|---|---|
| 尚未设置 | 尚未发起健康数据连接 | 提供设置入口 |
| 建立基线中 | 历史有效记录不足 | 显示已获得的有效夜晚及还需记录；不显示分数 |
| 当日核心输入缺失 | 最近主要睡眠或必要心率等缺失 | 显示“暂无法评估”及可操作原因 |
| 可选输入缺失 | 腕温、血氧或部分补充指标不可用 | 允许在已验证范围内计算；因素中注明未计入 |
| 等待新数据 | 有当日结果，新记录尚未可读／同步 | 保留最近结果并明确更新时间 |
| 仅有昨日结果 | 当天尚未具备评估条件 | 不将昨日分数冒充为今天；组件显示无当日结果 |
| 数据来源变化 | 换表、换指标口径或算法升级 | 重新检查基线适用性；必要时暂缓出分 |

HRV 当晚缺失是否仍可生成简化结果，取决于实机验证后的核心数据门槛；在该门槛确定前不得默认用最近一次 HRV 代替当晚记录。缺失数据也不能通过自动重新归一化权重，让结果无解释地升高。

### 5.4 算法必须满足的行为

- 相同有效输入、相同算法版本得到相同结果；展示文案能追溯到真实输入。
- 以个人同类数据基线比较，处理异常值；不能采用“HRV 越大就无限加分”的规则。
- 在其他条件不变时，新增明显负荷不能单独导致“恢复更好”；睡眠改善的影响方向应符合定义。最终整数分未变化是允许的。
- 午睡不是固定奖励分；只在有效记录出现后纳入评估，不能重复累计同一会话。
- 体能训练消耗与日活动总量存在重叠，不能作为两份独立消耗重复扣分。
- SDNN、公开 RMSSD、逐搏序列自算 RMSSD 分别标记来源、方法和时间尺度。首版使用一致的 SDNN 路径；不因新机存在 RMSSD 就自动混用历史。
- 算法权重、异常阈值、基线统计方式及分数校准另形成可验证规格；本方案不虚构“与苹果一致”的公式或准确率。

逐搏数据可用于自算其他 HRV 指标，但实际可读性与质量需验证，本版不为此增加手动测量流程。[SDNN](https://developer.apple.com/documentation/healthkit/hkquantitytypeidentifier/heartratevariabilitysdnn)、[RMSSD](https://developer.apple.com/documentation/healthkit/hkquantitytypeidentifier/heartratevariabilityrmssd)、[逐搏序列](https://developer.apple.com/documentation/healthkit/hkheartbeatseriesquery)

## 6. 旧机兼容与无法完全对齐的部分

| 差异 | 对用户的实际影响 | 本产品处理 |
|---|---|---|
| 旧机采样较稀疏 | 对短时间日间变化的捕捉可能较弱 | 优先建立稳定的夜间评估；只有有效日间数据才修正 |
| 苹果最终算法未公开 | 相同日期的分数可能不同 | 明确独立评估；不拿苹果分数作为逐分相等的验收标准 |
| 第三方后台与组件刷新受限 | 新数据出现后不能保证立刻更新 | 前台及时查询、后台按系统预算处理、显示时间 |
| 官方 Fitness 内部入口不可复用 | iPhone 需打开我们的 App | 保留相同“看分数—看因素”的任务路径 |
| 数据授权、地区及设备差异 | 部分指标没有记录或历史窗口受限 | 按实际可读数据评估，核心不足时不出分 |

苹果的“最快每 5 秒测心率”属于传感器测量能力，不等同于第三方每 5 秒获得新数据；HRV 采样也受静止状态影响。[苹果心率说明](https://support.apple.com/en-us/120277)

后台投递频率是上限而非送达保证。多数 watchOS 健康类型受每小时级别限制，组件另受系统调度影响；不把“全天更新”写成“实时监测”。[HealthKit 后台规则](https://developer.apple.com/documentation/healthkit/hkhealthstore/enablebackgrounddelivery%28for%3Afrequency%3Awithcompletion%3A%29)

首次设置可由 iPhone 完成，正常查看不要求每次先打开手机。Watch 无法获得新输入时仍可展示有时间标记的缓存。采用哪一端主算、如何同步基线由技术方案决定，必须验证日常佩戴场景与耗电后才能确定；不承诺手机离线期间始终生成最新分数。

## 7. 视觉与交互边界

设计以 watchOS 的快速查看、浅层导航、Digital Crown 竖向浏览和原生控件为基础。今日页先让用户看懂状态，因素解释保持短，长说明主要放到 iPhone。[Apple watchOS 设计指南](https://developer.apple.com/design/human-interface-guidelines/designing-for-watchos)

保留系统字体、黑色底、标准列表、按钮和过渡效果。主评分采用自己的数字与简洁刻度组合；三类因素使用有文字的原生列表项，不逐项照描官方主图形与因素按钮组合。颜色用于辅助状态，文字和形状也要能表达同一信息。

名称、App 图标、评分视觉、品牌色组合和解释文案独立创作。不同表壳尺寸、较大字号、VoiceOver 与减少动态效果应保持可读可用。SF Symbols 只按授权范围用于界面；不直接用作品牌或 App 图标。[SF Symbols 使用说明](https://developer.apple.com/cn/design/human-interface-guidelines/sf-symbols)

“样式微调”必须产生可辨识的独立整体观感，只改颜色或名字不是安全保证。审核关注复制与混淆，功能支持旧机并不豁免这些规则；无需因此新增产品功能。[审核指南 4.1、5.2.4、5.2.5](https://developer.apple.com/app-store/review/guidelines/)

产品介绍可写“适用于 Apple Watch Series 9 及更新的已支持机型，基于健康数据提供每日准备度参考”。不使用“苹果官方准备指数下放”“解锁官方功能”“与苹果算法同样准确”等表述。具体商业发行风险需按最终设计和发行地区评估，文档不保证审核结果。

## 8. 数据与隐私的最小约束

- 只请求实际使用的健康数据；不要求与评分无关的权限。不写入、覆盖用户原有睡眠、运动或生命体征记录。
- 默认本地处理，首版不搭建健康数据后台、不接入处理健康数据的广告或第三方分析服务。
- HealthKit 无样本、权限不足、同步延迟可能呈现相同结果；授权弹窗完成不代表所有读取权限获准。提示使用“未读到所需数据”，并给出检查路径。[授权说明](https://developer.apple.com/documentation/healthkit/authorizing-access-to-health-data)
- 尊重可读历史时间窗；多个来源记录需区分来源、去重和处理覆盖，不能简单相加。
- 清除本地派生结果仅影响本 App 缓存和评分，不删除 Apple 健康中的原始记录。
- 说明页用简短文字解释数据来源、算法独立性及一般健康参考用途；无需在每屏重复长免责声明。

## 9. 首版验收

| 场景 | 通过标准 | 对应需求 |
|---|---|---|
| S9 有足够可读历史 | 首次授权后利用历史初始化，不强制重等 7 晚 | R4 |
| 首次安装且无历史 | 显示基线建立状态与指导；页面和组件均不生成默认分数 | R4、R8 |
| 仅授权部分或近期数据 | 只使用可读范围；不把空数据明确断言为拒绝授权 | R4、R8 |
| 昨晚没有佩戴 | 不显示当天有效评分；昨日结果不能冒充今日 | R8 |
| 血氧／腕温缺失 | 不填零；在已验证降级规则内可继续并注明未计入 | R2、R8 |
| 核心 HRV 或心率不足 | 按确定的质量门槛暂缓评估；不沿用旧样本假装新测量 | R2、R8 |
| 分档边界 | 0、1、2、4、5、7、8、10 的文案和归类准确 | R1 |
| 活动后出现新记录 | 去重后更新因素与结果；运动记录和总消耗不重复计算 | R2、R5 |
| 午睡与跨夜睡眠 | 按会话归属处理；同一睡眠不重复计入、不机械固定加分 | R5 |
| 后台未被唤醒／手机暂不可达 | 展示带时间的可用结果；恢复后处理新输入，不声称实时 | R5、R6、R7 |
| Watch、iPhone、组件 | 同一评估版本的分数与状态一致；不同步时有时间依据 | R1、R6、R7 |
| 新旧 HRV 或换表 | 不混合口径和基线；切换／重建行为有明确解释 | R2、R4 |
| 因素详情与返回 | 从今日页容易进入和返回；系统入口不可用时仍能读到原因 | R3 |
| 小尺寸表壳／大字号 | 评分、状态和入口可读，辅助技术能表达分数与含义 | R1、R3、R6 |
| 同样输入重算 | 结果可重复，不发生随机跳分；原因与输入对应 | R1、R2 |
| 产品外观与描述 | 独立品牌和关键视觉，不暗示官方移植或相同算法 | 全部 |

不以“每次运动一定降 1 分”“午睡必定加 1 分”或“与苹果逐分相同”为验收条件。模拟器只能证明界面与部分流程；夜间样本、后台刷新、耗电和同步必须有真实设备证据。

## 10. 落地顺序与待验证事项

1. 核验 S9 的真实数据可用性：主睡眠、夜间心率、HRV 的数量和覆盖，运动评级、午睡及后台投递情况。只采集获授权的数据，不为提高采样频率要求开启无关医疗设置或全天伪造运动会话。
2. 固定独立算法规格：有效样本门槛、基线、睡眠与负荷计算、缺项行为、四档映射、解释规则和版本策略。验证前不宣传准确率或等价性。
3. 做最小设计稿：今日页、三个因素页、初始化／无数据状态、复杂功能和智能叠放；对应 iPhone 复用同一信息结构。
4. 完成产品闭环并在声明支持的机型、系统上验证；先检查 S9，再检查后续型号，不用新机结果代替旧机证据。
5. 依据实际能力完成商店描述、隐私说明与截图；审核材料展示真实数据流程及独立算法边界。

当前仍需验证：S9 样本质量阈值、后台与跨端更新延迟、是否需要 Watch 本地计算、实际耗电、受支持的系统跳转入口，以及最终视觉设计的审核风险。官方完整分数公式、数据不足处理和独立历史页仍属未公开／未确认内容，不据此扩展首版范围。

本方案中的产品范围及 watchOS 27 / iOS 27 系统下限已经明确；具体算法参数与上述实机事项需要在实现前后分别补齐证据。
